# Реестр рисков

Оценки качественные, для локального учебного стенда. Остаточный риск не означает
подтверждённую уязвимость. Ответственный за меры — Манько Аким.

| ID | Риск и основание | Вероятность | Влияние | Мера и остаток |
|---|---|---|---|---|
| S1 | Публикация учебных аккаунтов в интернете: demo-пароль известен | Средняя при ошибке размещения | Высокое | Loopback, APP_ENV=production запрещён; для публикации отключить seed, заменить сервер и добавить HTTPS |
| S2 | Попадание БД или .env в Git | Низкая | Высокое | .gitignore, проверка git ls-files; дампы содержат хеши паролей, хранить отдельно |
| S3 | Доступ к чужим заявкам при будущих изменениях API | Низкая | Высокое | Проверка owner_id в core; тесты 403 и состава CSV; code review каждой новой выдачи |
| S4 | Неизвестная уязвимость Python/ОС или dev-инструмента | Средняя | Среднее | OSV для Ruff, обновлять Python и ОС; проверка не покрывает все системные компоненты |
| O1 | Потеря файла SQLite при удалении папки | Средняя | Высокое | backup/restore проверены; перед сдачей и раз в день делать копию на отдельный носитель |
| O2 | Процесс не стартует из-за занятого 8080 | Средняя | Среднее | Проверка порта перед deploy; APP_PORT можно сменить; healthcheck и logs |
| O3 | Отказ при большой нагрузке | Средняя вне учебного масштаба | Высокое | 100 последовательных запросов — только smoke-замер; нет доказанной многопользовательской ёмкости |
| O4 | Копия на том же диске не спасает от поломки диска | Средняя | Высокое | Выносить backup отдельно; автоматического расписания нет |
| O5 | Сброс выбранного фильтра при обновлении страницы | Высокая | Низкое | BUG-03, открыто; повторно выбрать статус; позже хранить фильтр в URL |
